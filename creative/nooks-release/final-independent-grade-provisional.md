## Launch blockers and remaining checks

1. **P0 — Public email onboarding is not operationally established.** Existing evidence says custom SMTP is absent, confirmation remains enabled and public sign-in uses email OTP. Hosted fixtures were administratively confirmed and bypass delivery. Required closure: authorized existing sending provider/domain, real fresh-user delivery/code flow on the final public origin, expiry/retry, refresh, sign-out and switching accounts. Do not weaken verification to make the test pass.
2. **P1 — Final deployed public and native acceptance is absent.** Local source parity is not deployed runtime parity. Record the exact final revisions and URLs, verify API configuration and trusted asset/CSP behavior, then exercise the intended account/native paths, live membership changes, revoked access and save/reload recovery. Existing mounted native frames can retain old bundles.
3. **P1 — Fifty final assets and perceived quality need their final gates.** At this inspection 47 mapped hashes passed; three corrected pilots are still pending. Run the all-fifty exact-byte gate after final approval. Frame samples/full decode do not establish continuous repeated-loop quality, and loudness/clipping metrics do not establish pleasant listening. Actual listening remains a material gap given the user's request for realistic relaxing sound.
4. **P1 — Capacity and freshness claims need precise scope.** The successful report demonstrates 100 distinct identities, 100 sockets, 300 channels and 869 error-free API operations, p95 706 ms. It uses loopback HTTP with hosted Auth/DB, one room and a 120.414-second wall window that pauses API scheduling for 11.034 seconds during reconnects. It does not establish deployed HTTP capacity, long-duration behavior or 1,000 simultaneous users. WebSocket fanout latency is not visible UI freshness: normal hint cooldown is approximately 5–6.5 seconds, large-room cooldown 12–15 seconds, missed hints/native polling 45–60 seconds. State and test a supported workload/freshness target before advertising broad real-time scale.
5. **P1 — Operations remain unproven.** No newly inspected evidence closes alert delivery and ownership, backup coverage or an isolated hosted recovery exercise covering identities, SQL and private image bytes. Existing operational acceptance correctly separates local restore evidence from real recovery. Do not create destructive recovery drills on the live database or invent a completed operator sign-off.
6. **P2 — Mobile/accessibility and resource acceptance remain partial.** The browser report explicitly says the attempted viewport override did not alter dimensions, so no mobile pass exists. Check actual narrow layout/keyboard focus and perform a bounded repeated-scene browser resource check. The audio lifecycle regression is strong source evidence, not a measured memory profile.
