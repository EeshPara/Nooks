# Deliberate account changes and retained Studio edits

Source finding, October 8, 2026: Studio Close intentionally hides its retained editor. Unsaved fields live in owner-scoped `useCrashDraft`, which retains snapshots after render failure but does not preserve them after an ordinary account-key unmount. The old Account guard checked study notes/editors, active focus and saving work, but had no knowledge of hidden dirty Studio fields. Closing an unsaved Studio and then deliberately signing out could therefore discard those fields without warning.

Fresh drafts now compare their full payload to a stable pristine default with the same draft ID. This protects untitled scene/style/theme choices as well as text/image edits while keeping an untouched empty draft clean. Starting a new draft resets that baseline; loading/saving uses the authoritative saved baseline.

The bounded correction gives Studio an owner-bound imperative handle. Its account check reads the current draft, baseline, work and artwork/cancellation refs when invoked; it does not wait for a dirty-state effect. React owns handle installation and cleanup through `useImperativeHandle`; there is no asynchronous registration callback that can clear a newer owner handle. An unmounted or old-owner handle refuses approval. The parent removes Account and reopens Studio when its current owner's handle blocks the action. Other existing account guards still apply.

Studio explains why the transition was stopped. Save uses the existing save path; its action stays focusable while busy. Discard goes through the existing explicit leave confirmation and starts a fresh draft without calling draft deletion. Pending work is checked again before the confirmed reset. Saving, active image import/completion, pending cancellation and unsafe cancellation retention prevent discard and transition. A clean draft with an idle, already saved artwork request is safe to leave; the server owns that request. Ordinary Studio Close still hides without discarding or forcing focus while other dialogs remain open.

Validation: web 45/45, app 46/46 and cloud 45/45 focused/related Studio tests pass, along with TypeScript in all three targets. The nine account-guard tests exercise actual extracted AccountDialog verify/signOut handlers with injected callbacks, latest-ref edits/save status, dirty hidden Studio, imports/cancellation, explicit discard, work beginning after confirmation, stale owner/unmount callbacks, appearance-only choices and clean saved drafts. Two additional dismissal cases replay the actual StudioSurface effect setup → cleanup → setup without rerender and verify old cleanup cannot erase a newer close handler. These source-handler/effect tests complement, rather than replace, root's mounted browser acceptance.

Limits: this does not add automatic cross-tab sign-out recovery, preserve arbitrary unsaved forms across account changes, solve shared-library invitation lifecycle, or prove a live email/OTP switch. No authentication bypass or QA email is needed or introduced.

Selective app/cloud ports apply only the App and NookStudio deltas and the focused guard/dismissal tests, preserving their unrelated source differences. App retains one additional existing target-specific regression. No Site checkout or deployment is owned by this agent.

A temporary QA harness at `http://127.0.0.1:5194/` mounts the actual NookStudio under React StrictMode, with its real imperative handle, the extracted current parent account guard, simulated in-memory tool responses, and a device-scoped owner. Its account-attempt controls never call authentication. This provides real component lifecycle evidence with simulated tools/auth, not full-App or authenticated account acceptance. Root's first mounted pass found focus falling to body after Keep editing in the new discard flow. The fix restores focus to the invoking discard button only while the same Studio opening remains visible/current/topmost and focus has not moved elsewhere. Ordinary Close is unchanged. Root is rerunning the final mounted flows against frozen source.


The mounted StrictMode harness revealed a separate real lifecycle defect: StudioSurface installed its close handle during render but cleared it during effect cleanup. StrictMode effect replay could leave a reopened, held-save dialog without a close handle. Installation now occurs in the matching effect setup. The browser rerun must verify repeated close/reopen while a save is held, then release/save completion. Confirmed account-discard focuses the fresh Nook name field; cancel focuses the invoking discard button. Both delayed focus actions require the same visible/current/topmost presentation and do not override focus that moved elsewhere.
