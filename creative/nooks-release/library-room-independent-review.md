# Independent shared-library lifecycle review

October 8, 2026. **Source, selective-port and scoped mounted-component acceptance PASS for SharedLibraryRoom and LibraryInvitation. Deployment verification remains separate.** This review performed no live account, invitation, backend or deployment operation. Current release scores remain quality 7.5 and readiness 6.5.

The stateful room is keyed by owner, account status, share ID and invitation token. A changed identity or target therefore receives fresh private state during reconciliation instead of waiting for a reset effect. The initial request and every picker, refresh, save and comment completion are tied to a distinct effect lifetime. Cleanup invalidates that lifetime permanently, including StrictMode setup replay; a later mount cannot reactivate an old request. Success, error and finally paths all respect the lifetime.

The owner-bound imperative navigation guard reads synchronously maintained draft, comment and busy refs. A rejected invitation switch restores the accepted hash while preserving pathname, query and history state. It keeps edits mounted and gives save/cancel/send/clear guidance. An old owner's handle cannot inspect or block a new owner's navigation. Duplicate saves are rejected synchronously before a second tool request.

Independent review identified two remaining comment-loss paths: ordinary dialog Close did not include an unsent comment in its blocked condition, and StudyView exit could hide the material carrying that comment. Both are corrected. An already-open copy picker is also disabled while a comment, edit or request is active; the unsent comment remains visible and editable. Sending or clearing the comment releases the existing queued-dismiss behavior. Failure retains the draft and retry path.
