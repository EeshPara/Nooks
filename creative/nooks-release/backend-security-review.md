## Nonblocking limitations and required launch evidence

1. **Public onboarding and actual transport are separate launch gates.** Verify fresh real accounts, identity mapping, login/logout, authorized/unauthorized room subscriptions, membership revocation, reconnect and polling fallback against the deployed app. Database approval does not establish those product flows.
2. **No thousand-live-user capacity claim.** The provided report uses 1,000 stored memberships, 100,000 completed sessions, 32 concurrent local SQL connections and 640 operations per phase, with fsync disabled. It reports roughly 108 snapshots/second after changes and a heartbeat p95 regression in one run. This is useful correctness/relative evidence, not 1,000 hosted browsers, message-quota evidence or sustained production throughput. Measure end-to-end concurrent sessions, burst joins, snapshot fan-out, Auth/API quotas, lock waits and recovery on the existing plan before making that claim.
3. **Lossy invalidation is deliberate.** Suppressed hints have no trailing delivery guarantee. Periodic authorized snapshots/reconnect refreshes are required. Subscription authorization is cached; content must never be added casually to the hint payload. [Supabase channel authorization](https://supabase.com/docs/guides/realtime/authorization).
4. **Ordinary broadcast errors are isolated, not every database failure.** The inner exception handler catches ordinary `realtime.send` exceptions. PostgreSQL query cancellation/statement timeout is not caught by `WHEN OTHERS`, and throttle-table work occurs outside that handler. Do not promise that persistence survives arbitrary database timeout, disk, permission or lock failures. Current best-effort behavior is acceptable for this deployment.
5. **Throttle retention is bounded by historical topics, not active topics.** Account/room deletion leaves a tiny private throttle row. Plan cleanup/retention when churn becomes material; no high-cardinality topic can be inserted by a public client directly.
6. **Operational launch evidence remains missing:** backup/restore exercise, latency/error monitoring and alert ownership, production recovery and sustained hosted workload within plan limits. Add bounded deployment lock/statement deadlines and rerun advisors/ACL/aggregate checks after applying.
